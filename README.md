# رحلة تعافي — موقع التسجيل في حملات التوعية

موقع عربي بسيط ومتجاوب (RTL / Mobile First) لتسجيل المشاركين في حملات «رحلة تعافي»، وإرسال بيانات التسجيل إلى بريد مسؤول الحملة باستخدام EmailJS، دون إنشاء Backend أو قاعدة بيانات خاصة بالموقع.

> **حالة المشروع:** الواجهة جاهزة. لن يرسل النموذج أي بيانات قبل استكمال إعدادات EmailJS وreCAPTCHA v2 في `script.js` ولوحة EmailJS. هذا سلوك مقصود حتى لا يرسل الموقع بيانات إلى إعداد غير مكتمل.

## 1. محتويات المشروع

```text
rahlet-taafi/
├── index.html       # الصفحة الرئيسية، الاستمارة، وسياسة الخصوصية
├── style.css        # الهوية البصرية والتجاوب مع الشاشات
├── script.js        # التحقق والإرسال وإعدادات الحماية
└── README.md        # هذا الدليل
```

لا توجد قاعدة بيانات ولا API خاص ولا ملفات بيانات للمشاركين. قيم الاستمارة تبقى في ذاكرة صفحة المتصفح أثناء عملية الإرسال فقط؛ لا تُحفظ في `localStorage` أو `sessionStorage` أو ملفات المشروع.

## 2. متطلبات قبل التشغيل

- حساب GitHub لنشر الموقع مجانًا عبر GitHub Pages.
- حساب EmailJS.
- حساب Gmail الذي سيستقبل التسجيلات: `ahmedtety50@gmail.com`.
- موقع Google reCAPTCHA v2 من نوع **I'm not a robot Checkbox**.
- اتصال إنترنت؛ لأن الصفحة تستخدم EmailJS SDK وGoogle reCAPTCHA وصورة خلفية خارجية.

### تنبيه بشأن السن

الاستمارة مضبوطة حاليًا لقبول المشاركين من **18 إلى 100 سنة**. لا تغيّر الحد الأدنى إلى أقل من 18 عامًا قبل إضافة آلية موافقة ولي الأمر والتحقق من المتطلبات القانونية المناسبة للقُصّر.

## 3. إعداد EmailJS وربطه بـ Gmail

### الخطوة الأولى: إنشاء الحساب

1. افتح [EmailJS](https://www.emailjs.com/) وأنشئ حسابًا.
2. من لوحة التحكم افتح **Email Services**.
3. اختر **Add New Service** ثم اختر **Gmail**.
4. اضغط **Connect Account** وسجّل الدخول بحساب Gmail الذي سيستقبل إشعارات التسجيل.
5. وافق على صلاحيات الربط التي تعرضها Google، ثم احفظ الخدمة.
6. انسخ **Service ID** الذي يظهر بعد إنشاء الخدمة.

البريد الثابت للمستلم في هذا المشروع هو `ahmedtety50@gmail.com`. يجب أن يكون الحساب الذي ربطته في Gmail هو الحساب المقصود لاستقبال الرسائل، أو اضبط عنوان المستلم الثابت في القالب كما هو موضح أدناه.

### الخطوة الثانية: إنشاء Email Template

1. افتح **Email Templates** في لوحة EmailJS.
2. أنشئ قالبًا جديدًا، ثم سمّه مثلًا `Rahlet Taafi Registration`.
3. احفظ **Template ID**؛ ستحتاج إليه في `script.js`.
4. اضبط حقول القالب كما يلي:

| الحقل في EmailJS | القيمة |
|---|---|
| To Email | `ahmedtety50@gmail.com` (قيمة ثابتة، لا تجعلها متغيرًا يرسله الزائر) |
| From Name | `رحلة تعافي – تسجيل جديد` |
| From Email | استخدم العنوان الافتراضي الذي توفره خدمة Gmail المتصلة |
| Reply-To | اتركه فارغًا؛ الاستمارة لا تجمع بريدًا إلكترونيًا للمشارك |
| Subject | `تسجيل جديد – حملة بداية جديدة` |

5. ضع النص التالي في **Content**. استخدم الأقواس المزدوجة كما هي، فهذه أسماء المتغيرات التي يرسلها `script.js`:

```text
تسجيل جديد – حملة بداية جديدة

الاسم بالكامل: {{full_name}}
رقم التليفون: {{phone}}
النوع: {{gender}}
السن: {{age}}
الحالة الاجتماعية: {{marital_status}}
العنوان: {{address}}
الوظيفة: {{job}}
تاريخ ووقت التسجيل: {{registered_at}}

الموافقة: {{consent_text}}
```

يتضمن البريد الحقول الستة المطلوبة في مواصفات المشروع (الاسم، الهاتف، النوع، السن، الحالة الاجتماعية، التاريخ والوقت)، ويضيف العنوان والوظيفة اللذين تطلبهما الاستمارة حتى لا يجمعهما الموقع دون إيصال فائدتهما إلى مسؤول الحملة. لا يُرسل أي سؤال أو معلومة عن الحالة الصحية أو تاريخ التعاطي أو العلاج.

6. احفظ القالب وجرب زر **Test** من لوحة EmailJS قبل ربط الموقع. استخدم قيمًا تجريبية غير حقيقية.

### الخطوة الثالثة: تفعيل reCAPTCHA v2

1. افتح [Google reCAPTCHA Admin](https://www.google.com/recaptcha/admin/create).
2. أنشئ موقعًا جديدًا واختر نوع **reCAPTCHA v2 → "I'm not a robot" Checkbox**.
3. أضف النطاق الذي سينشر عليه الموقع، مثل `YOUR-USERNAME.github.io`. أضف `localhost` أيضًا إن كنت ستختبر محليًا.
4. احفظ الموقع وانسخ **Site Key**.
5. في EmailJS افتح القالب الذي أنشأته، ثم **Settings**.
6. فعّل **Enable reCAPTCHA V2 verification**، والصق **Secret Key** الذي أعطته Google في الحقل المخصص داخل لوحة EmailJS فقط.
7. لا تضع Secret Key الخاص بـ reCAPTCHA في ملفات الموقع مطلقًا.

يُحمّل `script.js` مربع reCAPTCHA تلقائيًا بعد وضع Site Key. ولن يسمح النموذج بالإرسال إذا لم يكن التحقق مفعّلًا أو لم يكتمل.

### الخطوة الرابعة: تعبئة إعدادات المشروع

افتح `script.js` وابحث في بدايته عن كائن `CONFIG`:

```javascript
const CONFIG = Object.freeze({
  EMAILJS_PUBLIC_KEY: "YOUR_EMAILJS_PUBLIC_KEY",
  EMAILJS_SERVICE_ID: "YOUR_EMAILJS_SERVICE_ID",
  EMAILJS_TEMPLATE_ID: "YOUR_EMAILJS_TEMPLATE_ID",
  RECAPTCHA_V2_SITE_KEY: "YOUR_RECAPTCHA_V2_SITE_KEY",
  MIN_AGE: 18,
  MAX_AGE: 100,
  MIN_FORM_AGE_MS: 2500,
  RATE_LIMIT_MS: 10000
});
```

استبدل القيم الأربع فقط:

- `EMAILJS_PUBLIC_KEY`: من **Account → General → Public Key** في EmailJS.
- `EMAILJS_SERVICE_ID`: معرّف خدمة Gmail التي أنشأتها.
- `EMAILJS_TEMPLATE_ID`: معرّف قالب التسجيل.
- `RECAPTCHA_V2_SITE_KEY`: مفتاح الموقع العام من لوحة Google reCAPTCHA.

**لا تضع EmailJS Private Key أو reCAPTCHA Secret Key هنا.** المفتاح العام الخاص بـ EmailJS وSite Key الخاص بـ reCAPTCHA مخصصان للاستخدام في الواجهة العامة. أما المفاتيح السرية فتبقى داخل لوحات الخدمات.

## 4. النشر على GitHub Pages مجانًا

### إنشاء Repository

1. سجّل الدخول إلى [GitHub](https://github.com/).
2. اضغط **New repository**.
3. اكتب اسمًا مثل `rahlet-taafi`.
4. اختر **Public** إذا كنت تستخدم GitHub Free؛ نشر GitHub Pages من مستودع خاص يتطلب خطة تدعم ذلك.
5. اضغط **Create repository**.

### رفع الملفات

1. افتح المستودع الجديد.
2. اختر **Add file → Upload files**.
3. ارفع `index.html` و`style.css` و`script.js` و`README.md` مع الحفاظ على وجودها في جذر المستودع، وليس داخل مجلد فرعي.
4. اضغط **Commit changes**.

### تفعيل GitHub Pages

1. افتح **Settings** داخل المستودع.
2. من القائمة الجانبية اختر **Pages**.
3. في **Build and deployment** اجعل **Source** هو `Deploy from a branch`.
4. اختر الفرع `main` والمجلد `/(root)`.
5. اضغط **Save**.
6. انتظر اكتمال النشر، ثم افتح رابط **Visit site** الذي سيظهر في صفحة Pages.

غالبًا سيكون الرابط بالشكل:

```text
https://YOUR-USERNAME.github.io/rahlet-taafi/
```

استبدل `YOUR-USERNAME` باسم حسابك الفعلي. وقد يستغرق أول نشر عدة دقائق.

### بعد معرفة رابط الموقع

- ارجع إلى reCAPTCHA وأضف نطاق `YOUR-USERNAME.github.io` ضمن النطاقات المسموح بها.
- في EmailJS افتح **Account / Security / Domains** وأضف نطاق الموقع إذا كانت خطتك تدعم قائمة النطاقات المسموحة. أدخل النطاق بصيغة البروتوكول والنطاق، مثل `https://YOUR-USERNAME.github.io`.
- أعد اختبار النموذج من الرابط المنشور، لا من معاينة GitHub.

## 5. اختبار التسجيل عمليًا

نفّذ الاختبار التالي قبل مشاركة الرابط مع الجمهور:

1. افتح الموقع المنشور في متصفح عادي، وانتظر تحميل reCAPTCHA.
2. املأ جميع الحقول ببيانات اختبار غير حقيقية، مثل اسم تجريبي ورقم اختبار لا يخص شخصًا آخر.
3. جرّب رقم هاتف غير صحيح وتأكد أن المتصفح يمنع الإرسال.
4. جرّب عمرًا أقل من 18 أو أكبر من 100 وتأكد من ظهور رسالة تحقق.
5. حاول إرسال النموذج دون تحديد الموافقة؛ يجب أن يرفض المتصفح الإرسال.
6. أكمل reCAPTCHA ثم أرسل النموذج مرة واحدة.
7. يجب ألا تظهر رسالة النجاح إلا بعد أن يعيد EmailJS استجابة نجاح فعلية.
8. افتح `ahmedtety50@gmail.com` وتحقق من وصول رسالة بعنوان `تسجيل جديد – حملة بداية جديدة` وبها المتغيرات السبعة وتاريخ ووقت التسجيل.
9. جرّب إرسالًا آخر مباشرة؛ يفترض أن يمنع قيد السرعة الإرسال المتتابع في الصفحة.
10. جرّب عمدًا تعطيل الإنترنت أو وضع Template ID خاطئًا في نسخة اختبار، وتأكد من ظهور رسالة فشل بدل رسالة نجاح.

**لا تستخدم بيانات مشاركين حقيقيين في الاختبارات.**

## 6. ما الذي يفعله المشروع لحماية الاستمارة؟

- تحقق واجهة المستخدم من الحقول المطلوبة، والعمر، وصيغة رقم الهاتف.
- لا يقبل إرسال النموذج دون الموافقة الصريحة.
- يضيف حقل Honeypot مخفيًا لالتقاط عدد من الإرسالات الآلية البسيطة.
- يرفض الإرسال السريع جدًا بعد فتح الصفحة.
- يمنع النقر المتكرر أثناء وجود طلب إرسال قيد التنفيذ.
- يفعّل `blockHeadless` في EmailJS.
- يضبط `limitRate` في EmailJS على طلب واحد كل 10 ثوانٍ.
- يشترط حل reCAPTCHA v2 قبل الإرسال.
- لا يحفظ بيانات الاستمارة في `localStorage` أو `sessionStorage` أو ملفات الموقع.
- لا يعرض أي تسجيل على صفحة عامة.
- لا يجمع معلومات صحية أو تفاصيل عن التعاطي أو العلاج.

## 7. حدود الخصوصية والأمان — اقرأ قبل النشر العام

هذا موقع Static؛ لذلك لا توجد طبقة خادم تتحقق من البيانات أو تخفي إعدادات الواجهة. من الطبيعي أن تظهر **EmailJS Public Key** وService ID وTemplate ID في ملفات JavaScript وأدوات المطور. يوضح EmailJS أن المفتاح العام مصمم للاستخدام في التطبيقات الأمامية؛ لكنه لا يجعل الواجهة محصنة من إساءة الاستخدام.

الحماية الفعلية تعتمد كذلك على إعدادات حساب EmailJS، وتفعيل CAPTCHA داخل القالب، وقصر المستلم على بريد الحملة، وتقييد النطاقات المسموحة إن كانت الخطة تدعم ذلك، ومراقبة سجل الاستخدام والحصص. إعدادات JavaScript ليست بديلًا عن تحقق الخادم، ويمكن لمهاجم تقني محاولة استدعاء الخدمة خارج واجهة الموقع. إذا كان حجم التسجيلات كبيرًا، أو كانت البيانات تستلزم سرية أعلى، فالأفضل نقل الإرسال إلى Backend أو Function مع التحقق من الخادم ومحددات معدل مركزية.

إرسال البيانات عبر EmailJS ثم Gmail يعني أن مزودي الخدمتين يعالجون البيانات وفق سياساتهم وشروطهم. كما أن البريد الإلكتروني العادي ليس وسيلة مناسبة لإرسال بيانات صحية أو علاجية حساسة؛ لذلك لا تطلب هذه البيانات ولا تستقبلها عبر هذا الموقع. احمِ حساب Gmail بالمصادقة متعددة العوامل، ولا تشارك الوصول إلى صندوق البريد إلا مع المختصين المخولين.

الموقع لا يحتفظ بنسخة من حقول الاستمارة على جهاز الزائر. لكن رسالة البريد تظل في صندوق البريد، وقد تحتفظ EmailJS بسجلات الطلب لفترة تتفاوت حسب الخطة والسياسة. عند طلب الحذف، ينبغي حذف الرسالة من Gmail والتحقق من سجلات EmailJS والنسخ/المجلدات ذات الصلة، ضمن ما تسمح به الأنظمة وسياسات المزود.

> **مهم:** لا يعتبر هذا المشروع مراجعة قانونية أو شهادة امتثال. قبل جمع بيانات أشخاص حقيقيين، راجع سياسة الخصوصية النهائية مع مسؤول الحملة أو مستشار قانوني، وحدد المسؤول عن البيانات ومدة الاحتفاظ والصلاحيات وإجراءات الحذف بما يتوافق مع القوانين السارية.

## 8. تخصيصات سريعة

- تغيير السن: عدّل `MIN_AGE` و`MAX_AGE` في `script.js`، وحدّث النص المقابل في `index.html` وسياسة الخصوصية.
- تغيير بريد الاستقبال: عدّل المستلم الثابت في **To Email** داخل EmailJS، ونصوص التواصل وسياسة الخصوصية في الصفحة.
- تغيير صورة الشروق: عدّل رابط صورة الخلفية في `.hero-photo` داخل `style.css` إلى صورة تملك حق استخدامها.
- تغيير الألوان: عدّل متغيرات الألوان في بداية `style.css`.
